## Data formats

**`tvguide-ds.xml`**

```xml
<movies>
  <movie tvgid="2">
    <name>Ever After</name>
    <rank>40</rank>
    <year>1998</year>
    <rating>PG-13</rating>
    <country>U.S.</country>
    <running-time>121</running-time>
    <genres><genre>Romance</genre></genres>
    <actor-list>
      <actor><name>Dougray Scott</name><role>Prince Henry</role></actor>
    </actor-list>
  </movie>
</movies>
```

**`imdb-ds.xml`** uses `<movie imdbid="...">` with a `<title>` element rather than
`<name>`, and lists titles in inverted form (`Fifth Element, The`).

**`ground_truth-1.txt`**, one line per pair, no header:

```
tvgid,imdbid,label
2,idm425250523376,1
3158,idm424634111472,0
```

98 rows, 73 positives and 25 negatives.

**`matches_jaro.txt` / `matches_mapping.txt`**, one line per matched pair:

```
tv_title,imdb_title,score
The Last Samurai,The Last Samurai,0.9333
```

Both contain 95 lines. The difference between the two is visible on titles with
leading articles: `matches_jaro.txt` still carries the raw IMDB form
(`Fifth Element, The`), while `matches_mapping.txt` carries the standardised form
(`The Fifth Element`).

## Pipeline

### 8.1 Parsing
* **a)** DOM parsing of `tvguide-ds.xml` with `xml.dom.minidom`, plus a recursive
  `get_details()` that walks a `<movie>` node and returns all attributes, text
  values and nested elements as a dictionary.
* **b)** SAX parsing of `imdb-ds.xml` with a custom `ContentHandler`, used because
  the IMDB file is too large to hold in memory as a DOM tree.
* **c)** Similarity comparison of the first five titles from each source using four
  measures from `jellyfish`: Levenshtein, Jaro-Winkler, Hamming and Soundex.
  Soundex is combined with Jaro-Winkler as a tie-breaker, since Soundex alone is
  only a binary phonetic equality check.
* **d)** Greedy best match per TV guide title above a threshold of 0.85, written to
  an output file.
* **e)** Same as d, but matches are made unique. Candidates are sorted by score
  descending and each IMDB title can only be assigned once.

### 8.2 Evaluation and richer matching
* **a)** Matched IMDB titles are resolved back to their `imdbid`, predictions are
  padded to the length of the ground truth, and precision, recall and F1 are
  computed with `sklearn.metrics.precision_recall_fscore_support` (micro average)
  for all four similarity measures. Jaro-Winkler performed best.
* **b)** Matching is extended beyond the title with a weighted composite score:

```
  score = w_title * jaro_winkler(titles)
        + w_year  * year_similarity(years)
        + w_actor * jaccard(actor_sets)
```

  `year_similarity` returns 1 on an exact match and decays linearly with a
  10-year window otherwise. Weights used: title 0.4, year 0.4, actors 0.2.
  Threshold 0.5. Output: `matches_jaro.txt`.

### 8.3 Mapping
Before matching, both sources are brought into a common representation:
* `standardize_title()` rewrites `Long Kiss Goodnight, The` into
  `The Long Kiss Goodnight` with a regex, and collapses repeated whitespace.
* `standardize_actor()` rewrites `Surname, Firstname` into `Firstname Surname`
  and normalises casing.

Matching is then rerun with weights title 0.4, year 0.3, actors 0.3.
Output: `matches_mapping.txt`.

### 8.4 Merging
A full-attribute parse of both sources (genres, production companies, director,
plot, keywords, location, roles), followed by a merge driven by
`matches_mapping.txt`. Merged records combine TV guide scheduling metadata with
IMDB descriptive metadata and are written to `merged_movies.json`.

## Notes and known issues

* Matching is a full cross product of TV guide titles against IMDB titles, so
  runtime grows with the size of `imdb-ds.xml`. Blocking on year or on first
  letter would be the obvious next optimisation.
* Evaluation uses micro-averaged precision, recall and F1 over padded prediction
  lists, so the three values coincide. A pairwise confusion matrix over the
  ground truth labels would be a stricter evaluation.
* Hamming distance only returns a meaningful value for equal-length strings and
  is included mainly for comparison.
* Ground truth contains 25 negative pairs, which the current evaluation does not
  exploit separately.

## ALBUM-88

`ALBUM-88.pdf` documents a separate DINT project: semantic deduplication of music
albums in the CDDB dataset (`cddb_discs2.xml`, with duplicate pairs in
`cddb_9763_dups.xml`).

Approach: minidom parsing, lowercase and diacritic stripping via
`unicodedata.normalize`, regex cleaning, then a weighted Jaro-Winkler composite
score over album title (weight 0.8) and artist name (weight 0.2), with a match
threshold of 0.85. Duplicates are merged with a rule-based strategy: scalar
attributes are taken from the record with the lower ID, genre and CID are unioned,
and track lists are unioned with a per-track similarity check so that near
duplicate track names collapse into one.

Reported results: precision 0.98, recall 0.885, F1 0.93.
